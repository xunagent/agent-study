# 选题与原始材料阅读

## 选择过程

用 `daily` 返回的主题、基础、目标、已读身份和候选队列开始。初学者优先解决一个明确问题：执行循环怎样停下、工具输出怎样回到模型、上下文为何需要压缩等。每篇只围绕一个主问题，附相关主题链接。

最多初筛 12 个候选，深读 3 个，发布 1 篇。限制是本次任务预算，不是要求找满。经典论文提供机制基础，官方最新更新用于理解工程取舍；不能只按发布日期排序。引用量和热度可辅助判断，但必须注明来源与日期，不编造引用数。

按以下标准综合选择：前置知识是否满足、与当前路线的关系、材料可读性、证据是否充分、对应用开发的价值。重要进展应涉及架构、接口、执行、工具、上下文、记忆或评测的实质变化。营销文案和简单改名不算。

## 来源与发现

- 论文：arXiv、OpenReview、ACL Anthology、会议公开论文页；聚合榜单只作发现线索，最终回到原文。
- 产品：用户选择的官方文档、工程博客、官方 GitHub 仓库与 releases/changelog；默认关注 Codex、Claude Code 和 Agent SDK。由官网进入文档，核对跳转和页面日期。
- 源码：确认官方仓库、模块路径、commit；同时阅读调用者、关键函数、配置和相关测试，避免仅凭 README 推断实现。
- 更新线索：对比已记录版本、章节、发布日期及重要接口变化。文档无版本号时保存访问日期及章节；内容变化后用新的版本标签追加。

检索结果的发布时间与论文版本日期分别记录。付费、失效、仅摘要或访问被阻止时，用 `candidate` 收藏并写明读取范围。不要用二手解读填充缺失的证据。

候选格式：

```json
{
  "source": {"kind": "paper", "url": "https://arxiv.org/abs/2210.03629"},
  "reason": "执行循环的基础材料，原文待核实",
  "topics": ["执行循环"],
  "discovered_at": "2026-11-07",
  "reading_scope": "abstract"
}
```

## 身份与版本

arXiv 版本共享一个材料身份；DOI 不区分大小写。官方文档使用规范链接与 fragment 章节作为身份，去掉营销参数。源码提供不含 commit 的稳定 `module_url`，`version` 必须是实际 commit hash，`url` 指向该 commit 下的具体路径。来源迁移或论文另有 DOI 时由宿主核对已有索引，避免把同一论文的两种链接重复发布。

## 阅读与质量检查

读完相关内容后再写：问题及旧方法不足、贡献、组件与输入输出、状态转移、证据、失败条件和代价。论文实验数据必须带基准、设置、指标、表格定位；官方产品说明没有对照实验时直接说明。

对闭源产品只描述公开行为。合理的实现猜测明确标为推断；流程图和伪代码若为教学重构，不写成“官方内部架构”。比较笔记时只读取学习正文，遵守个人感悟的读取边界。

不要翻译整篇论文。用自己的话解释机制，保留必要术语、原文链接和章节定位。引用采用短引文，遵守来源许可与宿主版权限制。
